動画取得方式 比較診断

accept属性ごとの動画取得動作を計測・比較するツール（Service Worker なし）

【調査結果】WebKit / iOS Safari の動画トランスコード動作

WebKit は WKFileUploadMediaTranscoder により、写真 App 経由で選択したすべての動画を H.264 にトランスコードします（AVAssetExportSession で最高品質プリセット）。
これは 2024 年の画像トランスコード修正（WebKit bug #267277）では対象外とされており、動画は「互換性のため」引き続きトランスコードが継続されています。

accept 属性は動画トランスコードに影響しません。どの値を指定しても Photos Picker 経由の動画は必ず H.264 に変換されます。
ファイル App 経由（UIDocumentPickerViewController）ではファイルを直接受け取るためトランスコードは発生しません。

PHPickerViewController + preferredAssetRepresentationMode = .current でも、物理デバイスでは HEVC→H.264 トランスコードが発生する事例が Apple Developer Forums で報告されています（未解決）。
⚠ 結論：PWA で写真 App からの動画トランスコードを回避する手段は現時点で存在しません。

計測タイミングの説明
B loadedmetadata ― JS 受け取り → コンテナ情報（解像度・長さ）取得
C loadeddata ― JS 受け取り → 最初のフレームがデコード済み（内部バッファ）
C2 表示確認 ― requestVideoFrameCallback: 最初のフレームが実際に画面に描画された瞬間
    C と C2 の差は通常 1〜2 フレーム分（約 16〜33ms）。C2 が大幅に遅い場合はレンダリングパイプラインの問題。
D canplay ― JS 受け取り → 再生可能と判断
E MP4 解析 ― moov ボックス探索・PTS 配列構築の所要時間
「A」時間（JSで計測不可）― ピッカーを開いてからファイルが JS に渡されるまで。 写真 App 経由では HEVC→H.264 トランスコード（約 20 秒）がここに含まれます。
